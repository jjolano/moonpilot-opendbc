# opendbc, as moonpilot uses it

This is `jjolano/moonpilot-opendbc`, a fork of `commaai/opendbc`. `master` is the fork branch and carries the fork's commits; `upstream` is commaai and stays there. Merge, never rebase, never force-push.

The fork's rules live in the superproject, and they apply here too:

@../AGENTS.md

## What the fork changed here

The safety layer, for the fork's lateral-only engagement: `opendbc/safety/moonpilot/lateral_engage.h` (the rule) and its declarations header, the twelve `controls_allowed` reads in `opendbc/safety/lateral.h` widened to `(controls_allowed || controls_allowed_lateral)`, the cruise main switch read into `acc_main_on` per brand with a lateral-engagement rx-check set per branch where a branch was needed (`modes/toyota.h`), Honda's own steering permit in `modes/honda.h` (it is the one brand that does not call `lateral.h`'s `steer_*_cmd_checks`), and the enable in `modes/volkswagen_common.h`/`_mqb.h`/`_meb.h`. The flags are `ToyotaSafetyFlags.LATERAL_ENGAGE` in `opendbc/car/toyota/values.py`, `HondaSafetyFlags.LATERAL_ENGAGE` in `opendbc/car/honda/values.py` and `VolkswagenSafetyFlags.LATERAL_ENGAGE` in `opendbc/car/volkswagen/values.py`. The tests are `opendbc/safety/tests/lateral_engage_common.py` plus one class per brand and rx-check branch in `test_toyota.py`, `test_honda.py`, `test_volkswagen_mqb.py` and `test_volkswagen_meb.py`. Everything else is upstream's.

## The invariants

- **`controls_allowed` keeps upstream's exact meaning.** It is stock ACC engagement, it is the only thing `get_longitudinal_allowed()` reads, and every longitudinal check, the brake/gas/regen exits and the heartbeat logic depend on it staying that way. The fork steers through the *second*, additive flag. Widening the first one instead hands the fork actuators it does not have, which is the single mistake this fork exists to avoid making.
- **The rule's steering-override term is inert on every brand the fork enables it for.** `lateral_engage_update` clears the permission on the rising edge of upstream's `steering_disengage`, and only `modes/tesla.h` ever sets that signal, so no Toyota, Honda or Volkswagen reaches the branch. The fork's safety test injects the flag to hold the rule itself; do not read it as a disarm that happens on the road, and do not add a brand equivalent without deciding that driver torque should stop steering — upstream's own answer there is to blend it.
- **A stock safety param must stay byte-identical to upstream's.** The fork's rx-check sets are duplicated per branch rather than edited in place, so a car without the fork's flag keeps upstream's array untouched. Keep that shape.
- **`ToyotaSafetyFlags.LATERAL_ENGAGE` (`16 << 8`), `HondaSafetyFlags.LATERAL_ENGAGE` (`32`) and `VolkswagenSafetyFlags.LATERAL_ENGAGE` (`4`) are one wire contract each** with `TOYOTA_PARAM_LATERAL_ENGAGE` (`modes/toyota.h`), `HONDA_PARAM_LATERAL_ENGAGE` (`modes/honda.h`, declared per init) and `FLAG_VOLKSWAGEN_LATERAL_ENGAGE` (`modes/volkswagen_common.h`). Change a pair together or not at all; a mismatch is a param the car never enables. The three bit positions are free in each brand's own flag space and were chosen for that, not for a common value.
- **What a brand has to have to be listed is an already-checked cruise main switch, and that is a rate requirement rather than a taste one.** The rule arms on `acc_main_on`'s rising edge together with the heartbeat, so a brand whose `acc_main_on` is never set is inert rather than dangerous — which is exactly why the openpilot-side gate excludes those cars instead of shipping a toggle that does nothing. Concretely: Honda decodes `SCM_FEEDBACK` 0x326 (10 Hz) or `SCM_BUTTONS` 0x1A6 (25 Hz), and both are already rx-checked at those rates; Volkswagen MQB reads `TSK_06` (50 Hz) and MEB reads `Motor_51` (50 Hz), already checked. **No new rx check was needed for any of the three**, and none should be added without one: `safety.h` fails any checked message below 10 Hz and on a lagging counter, and that path clears `controls_allowed`, which is a whole-car failure rather than a degraded feature. Volkswagen PQ and MLB are excluded by flag: PQ sets `acc_main_on` only under `volkswagen_longitudinal`, and MLB sets it nowhere.
- **Honda's steering permit is its own and has to be widened separately.** Honda is the only brand whose `tx_hook` tests `controls_allowed` for steering (`0xE4`/`0x194`) instead of calling `lateral.h`'s `steer_torque_cmd_checks`/`steer_angle_cmd_checks`/`steer_curvature_cmd_checks`, so the twelve widenings in `lateral.h` do not reach it. Miss that one line and the feature reports itself enabled while the car refuses to steer.
- **The enable rides the safety param, not `alternative_experience`.** `toyota_init` must see it to pick the rx-check set, and the param reaches `init` by construction while the alternative experience only happens to be set first by pandad. Honda and Volkswagen read it the same way, from their own inits. The three bits are single bits on purpose: `GET_FLAG` is `(value & mask) == mask`, an equality test, so a mask that were two bits set would stop matching the moment one of the pair came from anywhere else.
- **Import the fork's test mixin by module, never by name.** `LateralEngageSafetyTest` is an ABC whose `setUpClass` skips when it is collected directly, and unittest collects every `TestCase` a module imports by name: `from ...lateral_engage_common import LateralEngageSafetyTest` puts the skipped ABC into the importing module's ids (`test_toyota.py`, `test_honda.py` and both Volkswagen modules), where it sorts before the concrete `TestToyota*` classes and wins `mutation.py`'s one-id-per-(method, module) dedup. Every fork mutant then survives a suite that reports green. `import opendbc.safety.tests.lateral_engage_common as lateral_engage_common` and qualify the base classes.
- **The mixin's steering-disengage case is injected, not observed.** `test_lateral_engage_disarms_on_steering_disengage` drives `steering_disengage` through the harness because no listed brand sets it (previous bullet); it holds the rule, not a road behavior. Keep its docstring saying so.
- **The seam in `lateral.h` takes upstream's blank line, so no line below it moves.** `mutation.py` carries a line-keyed allowlist of known surviving mutants (`known_survivors`: `lateral.h` 188, 218 and 219). A line inserted above them shifts every number and the allowlist silently stops matching, which turns three upstream-known survivors into a red gate. Keep this file's line count identical to upstream's.
- **This tree is on openpilot's boot path.** `card`, `selfdrived` and `plannerd` import from here at start, so keep module-level imports light — the fork's init-path rule applies inside this repo too.

## Gates

`opendbc/safety/tests/test.sh` is the first of two. The second is upstream's `opendbc/safety/tests/mutation.py`, which comma's CI runs as the `Safety mutation tests` job and exits 1 on any mutant the suite leaves alive — so a fork test has to fail when the rule it covers is mutated, not merely pass. Both are run from `opendbc_repo` with this repo's own `.venv/bin/python`. Comma's rule for a fork that edits `opendbc/safety/` is that the whole suite is preserved and passes, and that script enforces it mechanically with 100% line coverage of every non-libsafety safety file. Three things fall out of that:

- **New C is unreachable from the tests until it is exposed in the harness**: a new global or function needs a shim in `opendbc/safety/tests/libsafety/safety.c` and a declaration in `libsafety_py.py`'s `ffi.cdef`, or the coverage gate can never be satisfied.
- **The coverage data has to start clean.** `test.sh` removes `*.gcda` but not `*.gcno`, so stale objects from an earlier build make `gcovr` merge two line maps for one header and abort; remove both before a gate run that follows a source change.
- **MISRA runs from `opendbc/safety/tests/misra/test_misra.sh`** and needs `cppcheck`: run it with this repo's own `.venv/bin/python` so its default `import cppcheck` resolves, and set `CPPCHECK_DIR` to that package's `install` directory. A clean compile is not a clean check.

`ruff check .`, `ty check`, `codespell` and `cpplint` are the rest of `lefthook.yml`'s gate — and `codespell` only sees files git knows about, so `git add` first.
