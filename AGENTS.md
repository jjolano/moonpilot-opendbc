# opendbc, as moonpilot uses it

This is `jjolano/moonpilot-opendbc`, a fork of `commaai/opendbc`. `master` is the fork branch and carries the fork's commits; `upstream` is commaai and stays there. Merge, never rebase, never force-push.

The fork's rules live in the superproject, and they apply here too:

@../AGENTS.md

## What the fork changed here

The safety layer, for the fork's lateral-only engagement: `opendbc/safety/moonpilot/lateral_engage.h` (the rule, with its two arming modes — `LATERAL_ENGAGE_ARM_SWITCH` on the car's own cruise main switch and `LATERAL_ENGAGE_ARM_HOST` on openpilot's engaged heartbeat) and its declarations header, the twelve `controls_allowed` reads in `opendbc/safety/lateral.h` widened to `(controls_allowed || controls_allowed_lateral)`, the cruise main switch read into `acc_main_on` for the three brands whose modes already decode it — Toyota's decode and its per-branch rx-check set are the fork's, `modes/toyota.h`; Honda's and Volkswagen's are upstream's — Honda's own steering permit in `modes/honda.h` (it is the one brand that does not call `lateral.h`'s `steer_*_cmd_checks`), and one param bit per brand in that brand's own safety mode, armed with `lateral_engage_set_enabled(..., arm)` in every init that installs the mode. Every brand openpilot drives is armed. The mirrors are `LATERAL_ENGAGE` in each brand's `opendbc/car/<brand>/values.py` `*SafetyFlags` class, and `moonpilot/tests/test_engage.py` reads the mode headers and fails if a mirror and a constant drift apart.

## The invariants

- **`controls_allowed` keeps upstream's exact meaning.** It is stock ACC engagement, it is the only thing `get_longitudinal_allowed()` reads, and every longitudinal check, the brake/gas/regen exits and the heartbeat logic depend on it staying that way. The fork steers through the *second*, additive flag. Widening the first one instead hands the fork actuators it does not have, which is the single mistake this fork exists to avoid making.
- **The rule's steering-override term is live on exactly one armed brand, and it holds rather than edges.** `lateral_engage_update` clears the permission for as long as upstream's `steering_disengage` is asserted — level-held, because a host-armed brand would otherwise take the permission straight back on the next heartbeat with the driver still holding the wheel. Only `modes/tesla.h` ever sets that signal, so Tesla is the one armed brand where the branch fires; on every other brand a driver's torque is upstream's blending path, and the fork's safety test injects the flag to hold the rule itself there. Do not add a brand equivalent without deciding that driver torque should stop steering — upstream's own answer there is to blend it.
- **A stock safety param must stay byte-identical to upstream's.** The fork's rx-check sets are duplicated per branch rather than edited in place, so a car without the fork's flag keeps upstream's array untouched. Keep that shape.
- **Each armed brand's bit is one wire contract.** `LATERAL_ENGAGE` in that brand's `opendbc/car/<brand>/values.py` — `ToyotaSafetyFlags` (`16 << 8`), `HondaSafetyFlags` (`32`), `VolkswagenSafetyFlags` (`4`), `GMSafetyFlags` (`8`), `FordSafetyFlags` (`4`), `ChryslerSafetyFlags` (`4`), `SubaruSafetyFlags` (`8`), `HyundaiSafetyFlags` (`1024`), `MazdaSafetyFlags` (`1`), `MgSafetyFlags` (`1`), `NissanSafetyFlags` (`2`), `PsaSafetyFlags` (`1`), `RivianSafetyFlags` (`2`), `TeslaSafetyFlags` (`4`) — against `TOYOTA_PARAM_LATERAL_ENGAGE` / `HONDA_PARAM_LATERAL_ENGAGE` / `FLAG_VOLKSWAGEN_LATERAL_ENGAGE` / `<BRAND>_PARAM_LATERAL_ENGAGE` in that mode's header. Change a pair together or not at all; a mismatch is a param the car never enables, and `moonpilot/tests/test_engage.py` now reads the headers and fails on one in either direction. Every bit is free in its own brand's flag space and was chosen there, not for a common value.
- **A brand is listed with a free param bit and one init line; ARM_HOST needs no car signal at all, and ARM_SWITCH — the three brands that already decode the switch — is the mode that carries a rate requirement.** The rule arms on `acc_main_on`'s rising edge alone — deliberately not on the heartbeat, which reaches the panda only with pandad's 10 Hz tick, after openpilot has begun to steer; the heartbeat only *expires* the permission, and only once it has been missing for the grace window — so a brand whose `acc_main_on` is never set is inert rather than dangerous, which is why those brands are armed on the host instead of being excluded. Concretely: Honda decodes `SCM_FEEDBACK` 0x326 (10 Hz) or `SCM_BUTTONS` 0x1A6 (25 Hz), and both are already rx-checked at those rates; Volkswagen MQB reads `TSK_06` (50 Hz) and MEB reads `Motor_51` (50 Hz), already checked. **No new rx check was needed for any of the three**, and none should be added without one: `safety.h` fails any checked message below 10 Hz and on a lagging counter, and that path clears `controls_allowed`, which is a whole-car failure rather than a degraded feature. Volkswagen PQ and MLB are armed on the host by flag: PQ sets `acc_main_on` only under `volkswagen_longitudinal`, and MLB sets it nowhere.
- **Honda's steering permit is its own and has to be widened separately.** Honda is the only brand whose `tx_hook` tests `controls_allowed` for steering (`0xE4`/`0x194`) instead of calling `lateral.h`'s `steer_torque_cmd_checks`/`steer_angle_cmd_checks`/`steer_curvature_cmd_checks`, so the twelve widenings in `lateral.h` do not reach it. Miss that one line and the feature reports itself enabled while the car refuses to steer.
- **The enable rides the safety param, not `alternative_experience`.** `toyota_init` must see it to pick the rx-check set, and the param reaches `init` by construction while the alternative experience only happens to be set first by pandad. Honda and Volkswagen read it the same way, from their own inits. The three bits are single bits on purpose: `GET_FLAG` is `(value & mask) == mask`, an equality test, so a mask that were two bits set would stop matching the moment one of the pair came from anywhere else.
- **Import the fork's test mixin by module, never by name.** `LateralEngageSafetyTest` is an ABC whose `setUpClass` skips when it is collected directly, and unittest collects every `TestCase` a module imports by name: `from ...lateral_engage_common import LateralEngageSafetyTest` puts the skipped ABC into the importing module's ids (`test_toyota.py`, `test_honda.py` and both Volkswagen modules), where it sorts before the concrete `TestToyota*` classes and wins `mutation.py`'s one-id-per-(method, module) dedup. Every fork mutant then survives a suite that reports green. `import opendbc.safety.tests.lateral_engage_common as lateral_engage_common` and qualify the base classes.
- **The mixin's steering-disengage case is injected on every brand but Tesla.** `test_lateral_engage_disarms_on_steering_disengage` drives `steering_disengage` through the harness because only Tesla's rx hook sets it (previous bullet); on the rest it holds the rule, not a road behavior. Keep its docstring saying so.
- **The seam in `lateral.h` takes upstream's blank line, so no line below it moves.** `mutation.py` carries a line-keyed allowlist of known surviving mutants (`known_survivors`: `lateral.h` 188, 218 and 219). A line inserted above them shifts every number and the allowlist silently stops matching, which turns three upstream-known survivors into a red gate. Keep this file's line count identical to upstream's.
- **This tree is on openpilot's boot path.** `card`, `selfdrived` and `plannerd` import from here at start, so keep module-level imports light — the fork's init-path rule applies inside this repo too.

## Gates

`opendbc/safety/tests/test.sh` is the first of two. The second is upstream's `opendbc/safety/tests/mutation.py`, which comma's CI runs as the `Safety mutation tests` job and exits 1 on any mutant the suite leaves alive — so a fork test has to fail when the rule it covers is mutated, not merely pass. Both are run from `opendbc_repo` with this repo's own `.venv/bin/python`. Comma's rule for a fork that edits `opendbc/safety/` is that the whole suite is preserved and passes, and that script enforces it mechanically with 100% line coverage of every non-libsafety safety file. Five things fall out of that:

- **New C is unreachable from the tests until it is exposed in the harness**: a new global or function needs a shim in `opendbc/safety/tests/libsafety/safety.c` and a declaration in `libsafety_py.py`'s `ffi.cdef`, or the coverage gate can never be satisfied.
- **The coverage data has to start clean.** `test.sh` removes `*.gcda` but not `*.gcno`, so stale objects from an earlier build make `gcovr` merge two line maps for one header and abort; remove both before a gate run that follows a source change.
- **The gate is runnable without the script, and often has to be.** `test.sh`'s last step wants `gcovr`, which this venv does not carry — `python -m venv /tmp/gcovr && /tmp/gcovr/bin/pip install gcovr` is enough — and the coverage invocation is worth reproducing by hand, because it is where a green gate is easiest to misread.
- **`gcovr -d` consumes the coverage data it reads, and the exclusion is relative to the root.** The first means the coverage gate is one-shot per suite run: run the tests first, and re-run them before a second `gcovr`, or it reports 0% for every file rather than failing loudly. The second means the command has to run from `opendbc/safety/tests` with `-r ./../ -e '^libsafety'`, as `test.sh` does; from the repo root the same flags leave the libsafety shim in the report at 77% and look like a failing fork.
- **MISRA runs from `opendbc/safety/tests/misra/test_misra.sh`** and needs `cppcheck`: run it with this repo's own `.venv/bin/python` so its default `import cppcheck` resolves, and set `CPPCHECK_DIR` to that package's `install` directory. A clean compile is not a clean check.

`ruff check .`, `ty check`, `codespell` and `cpplint` are the rest of `lefthook.yml`'s gate — and `codespell` only sees files git knows about, so `git add` first.
